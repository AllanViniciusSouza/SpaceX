How the buttons behave (FB_VTD_ManualControl)
  • Mode: accepted only at standstill with no JOG / RUN / START active (the drive stops on every PO 6 change). Otherwise the message bar shows "Mode change refused".
  • JOG: hold-to-run. After ENABLE or a mode change both jog buttons must be released once before a jog is accepted. After tJogMaxTime the jog stops until the button is released.
  • RUN − / RUN + (200): one tap starts, the axis keeps running; STOP ends it. Reversing requires STOP first. Speed changes are applied live.
  • START: 400 = go to the absolute target · 401 = move the relative distance (START after a STOP continues to the original target) · 300 = referencing, released automatically when referenced. 400/401 need "Referenced".
  • ENABLE off while turning: the axis first stops with the PO 4 ramp, then the enable is removed (after 5 s at the latest).
  • Raw PD write on the screen Visualization and this screen never write at the same time: the raw write is refused while ENABLE is active here, and this screen is inhibited while the raw write is active.
Test day checklist
  • Link IO_VFDs.VTD_WcState and IO_VFDs.VTD_EcState in XAE first. Without them "Communication OK" stays off and ENABLE is always refused.
  • Check the user units of speed and ramps in MOVISUITE, then enter a low max speed and the ramps (item 23). They are persistent.
  • E-stop / safety circuit reset → "STO inactive" green. Software limit switches stay active (never deactivated by the PLC).
  • Mode JOG speed · 101, speed 5–10 %, ENABLE, short JOG + → confirm whether + is up or down and write it on the button text.
  • Test STOP, SOFTWARE STOP (stops with FCB 14 and brake), RESET, ENABLE again.
  • Then SPEED · 200 with RUN ±, REFERENCE · 300, and POS 400 / 401 with small distances.
  • The hold-to-run JOG depends on the HMI connection. If the browser / HMI is closed with a button pressed, the jog runs until tJogMaxTime → keep that time short and the hardwired E-stop within reach.
